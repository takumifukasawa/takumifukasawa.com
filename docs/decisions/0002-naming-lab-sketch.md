# 0002: tier 1 の命名 — 場所は `lab`、1 件は `sketch`

- 日付: 2026-10-08
- 状態: 採用（2026-10-08）
- 関連: `0001-overall-architecture.md`

## 背景

当初案では tier 1（日々の制作）を `daily` と呼び、repo を `daily-experiments`、実行環境のサブドメインを `lab.` としていた。
2 つの問題がある。

1. **`daily` は頻度を約束する。** URL（`/daily/001-...`）は X の投稿から恒久的に参照されるので後から変えられない。週 3 になった時点で名前のほうが先に嘘になり、構造が制作のブレーキになる。目的（制作量の最大化）と逆。
2. **同じものに名前が 3 つある。** `daily`（URL）/ `daily-experiments`（repo）/ `lab`（サブドメイン）。1 件公開するたびに頭の中で対応を取り直すのは、毎日踏む摩擦になる。

## 採用案

**概念に 1 語だけ割り当て、URL・ディレクトリ名・collection 名・R2 の key prefix を同じ語にする。選ぶ語は `lab`。**

| 役割 | 値 |
|---|---|
| サイトの索引 | `takumifukasawa.com/`（`/lab/` の独立した索引は P2。sketch の詳細ページは作らない） |
| Astro の collection | `lab`（`src/content/lab/*.md`） |
| 作品のソース | `lab/<NNN-slug>/`（サイトと同じ repo） |
| 作品の URL | `takumifukasawa.com/lab/<NNN-slug>/` |
| R2 の key prefix | `lab/<NNN-slug>/...` |
| 公開 CLI | `pnpm lab:add <slug>` |

**1 件の呼び方は `sketch` / スケッチ。** 文章・UI 文言・X の投稿でだけ使い、URL と識別子には出さないので、後からいつでも変えられる。

**`daily` は構造から完全に外す。** 使いたければ X のハッシュタグ（`#daily`）として付けるだけ。frontmatter にも URL にも持たない。

### なぜ `lab`（単数）か

- **場所の名前なので何も約束しない。** 頻度・完成度・媒体のどれにも縛られない。10 分の GLSL スケッチも Houdini の検証も WebGPU の compute 実験も、同じ場所に無理なく置ける。
- `/works/` `/notes/` が複数形なのに `/lab/` が単数なのは、**前者が「項目の種類」を指し、後者が「場所」を指す**ため。項目は sketch であって lab ではない。意味の違いなので不統一ではない。
- `labs` は Google Labs / Adobe Labs のように「組織のプログラム名」の響きがあり、個人サイトでは借り物になる。1 文字短いぶん URL としても打ちやすい。

### 「量」と「継続」の見せ方

名前で主張せず、**データで見せる**。`/lab/` の索引に `date` から算出した日付密度グリッド（contribution graph 風）を置く。
名前は何も約束せず、実績だけが見える。これは `spec/site-v0.md` の P2 に置く（10 件の時点で出すと空白だらけで逆効果のため）。

### 3 階層の表現

tier ごとに collection を作らない。**2 collection + リンク 1 本**で出す。

| 階層 | 表現 |
|---|---|
| sketch（300〜500） | `lab` の 1 件 |
| technical study（20〜30） | `lab` の 1 件 + それを解説する `notes` 1 本（`notes` 側の `relatedLab` で参照。lab 側は逆リンクを持たない） |
| major work（4〜6） | `works` の 1 件（`relatedLab` で元になった sketch を指す） |

## 落選案と落選理由

**`daily` のまま** — 上記の理由 1・2。採らない。

**`sketches`** — 1 件の呼び方と名前が一致して分かりやすいが、「軽い・速い」の含意があり、Houdini の重い検証や時間をかけた技術実験に対して少しずれる。URL としても `lab` より長い。1 件の呼称としては採用し、URL 用の語には使わない。

**`experiments`** — 妥当だが 11 文字で長く、技術検証寄りの含意がある。「密度 / 静けさ / 侵食」のような感覚テーマから作る作品にも技術検証の枠が被る。採らない。

**`labs`（複数）** — 上記のとおり組織名の響き。採らない。

## 影響・やり直す条件

- `/lab/` の URL は X から恒久参照されるので、**最初の X 投稿より前に確定させる**（= P0 着手前）。それ以降は変えない。
- sketch という呼称は URL に出ないので、いつでも変えてよい（この決定を覆す必要はない）。
- **やり直す条件**: tier 1 の性質が「実験」から大きく外れた場合（例: 完成作品のみを出す運用に変わった場合）。その場合は新しい決定を足し、旧 URL は 301 で維持する。
