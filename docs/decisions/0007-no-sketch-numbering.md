# 0007: sketch の識別子に連番を持たせない — `lab/<slug>/`

- 日付: 2026-10-11
- 状態: 採用
- 関連: `0001-overall-architecture.md`, `0002-naming-lab-sketch.md`, `0006-lab-archives.md`（「番号は返さない」の節をこれで廃止）, `../spec/content-model.md`

## 背景

sketch の識別子は当初から `lab/<NNN-slug>/`（3 桁の連番 + スラグ）だった。これは決定として書かれたことがなく、
0001 の時点から doc 全体に `<NNN-slug>` という形で埋まっていた。

決定 0006（没の置き場）を書く過程で、この番号に**所有権**という概念が必要になった — 棚上げした sketch は
番号を持ち続けるのか、返すのか。同じ日に判断が 2 回変わり、`numberOwner()` とテスト 5 件、0006 の 1 節を費やした。
そこで前提に戻った: **この番号は何の仕事をしているのか。**

## 採用案: 連番を持たない。識別子はスラグだけ

`lab/greeble/` → `public/lab/greeble/` → `takumifukasawa.com/lab/greeble/`

番号が担っていると思っていた仕事を 1 つずつ見ると、ほとんどが別の場所で既に解決していた。

| 番号の仕事 | 実際 |
|---|---|
| サイトの並び順 | **使っていない。** 索引は `date` の降順（`src/pages/index.astro`）。後から「前の方に差し込みたい」も `date` で済む |
| 一意性 | **ディレクトリ名が保証する。** FS が重複を許さず、`pnpm new` は既存ディレクトリを拒否する |
| 名前を考えずに作り始められる | スラグ（`greeble`）は結局決めている。番号が省いていたのは衝突確認だけで、それは自動 |
| `ls lab/` が時系列に並ぶ | **本物の損失。** ただし「最近何を作ったか」は `git log` のほうが強い |
| 同テーマを再訪したとき名前を使い回せる | **本物の損失。** `001-greeble` と `047-greeble` が両方 `greeble` でいられた。今後は `greeble-dense` のように区別する |

払っていたコストは 2 つ。**URL に恒久的に意味の無い数字が残る**こと（`/lab/001-greeble/`）と、
**番号の所有権という概念**。後者が 0006 を膨らませた当のものだった。

失う 2 つには代替があり、片方（テーマ名の区別）は**スラグが実際にどれなのかを語るようになる**ので改善でもある。

### いま決める理由

決定 0002 が「`/lab/` の URL は X から恒久参照されるので、最初の X 投稿より前に確定させる」と書いている。
公開済みの sketch は 0 件なので、**ここが変えられる最後の地点**。1 件でも出した後なら、この決定は採らない。

## 落選案と落選理由

| 案 | 落選理由 |
|---|---|
| 連番を残す（`lab/001-greeble/`） | 上の表のとおり、番号が単独で担っている仕事は `ls` の時系列だけ。恒久 URL に残る数字と「番号台帳」という概念は、それより高くつく |
| 日付プレフィックス（`lab/2026-10-11-greeble/`） | 時系列順を保ちつつ番号の払い出しが消えるが、frontmatter の `date` と二重管理になる（`../spec/content-model.md` の「導出できるものは持たない」に反する）。同じ日に 2 件作れば結局 suffix が要り、制作日と公開日がずれたときにどちらを書くかも決める必要が出る |
| ディレクトリだけ番号を持ち、URL はスラグだけ | `lab/<slug>/` → `public/lab/<slug>/` → URL が同名で一直線なのが決定 0001 の核。ここに対応表を 1 枚挟むと、スクリプトと検査の全部がそれを知る必要が出る |
| 連番を 4 桁にする | 300〜500 件なら 3 桁で足りる。桁数の問題ではなかった |

## 影響・やり直す条件

- `SLUG_PATTERN` が `/^[a-z0-9]+(-[a-z0-9]+)*$/` に。`numberOwner()` と `labArchivesDir` は削除。
  `pnpm new` は `lab/<slug>/` の存在だけを見る（これが `pnpm new core` で `lab/core/` を潰す事故も同時に止める）
- コマンドは `pnpm new greeble "Greeble"` / `pnpm dev:lab greeble` / `pnpm lab:add greeble`
- `SLUG_PATTERN` が **スラグの唯一の入力ゲート**になった（番号という形式的な縛りが無くなったので）。
  スラグはディレクトリ名・content entry の id・R2 の key・URL を兼ねるので、通ってしまった文字は恒久的。テストはここに寄せた（`scripts/lib/lab.test.ts`）
- `core` がスラグとして通る形になった。拾ってはいけない呼び出し側は `index.html` の有無で弾く（`webSketchSlugs()`）
- **やり直す条件**: `lab/` が 100 件を超えて一覧として探しにくくなったとき。
  ただし番号を戻すのではなく**索引側**（`/lab/` のページ）で解く。公開済みの URL は変えない
