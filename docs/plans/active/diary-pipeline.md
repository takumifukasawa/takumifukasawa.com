# diary-pipeline — Obsidian で書いた日記（とブログ）をサイトに取り込む

- 開始: 2026-11-28
- 状態: 計画中（2026-11-28 に「日記の取り込みからやる」で合意。実装はまだ）
- 関連: `blog-migration.md`（タスク 4 の組み換え）, `../../spec/content-model.md`

## 目的（何ができれば完了か）

文章は全部 Obsidian（private の vault リポジトリ `obsidian-personal`）で書き、`publish: true` を付けたものだけがサイトに出る。
まず日記（`01_daily/`）を取り込み、同じ仕組みにブログ・作品の作り方の文章を後から乗せる。

**日記の本文はこの公開リポジトリに一切コミットしない**（private の日記が混ざる。2026-11-27 のユーザーの指示）。

## 受け入れ条件

- [ ] vault の `01_daily/**/*.md` のうち `publish: true` のものだけが、private の中継リポジトリに写る（`publish: false` / 無しは写らない。検査で確認）
- [ ] `publish` を `true` から `false` に戻した日は、次の同期で中継リポジトリから本文・画像とも消え、サイトからも消える（中継リポジトリは毎回「今 `true` のもの」の写しにする。検査で確認）
- [ ] 中継リポジトリに写るのは本文と、本文から参照されている画像だけ（vault の他のフォルダ・`99_attachments/` の参照されていない画像は写らない）
- [ ] 写した画像には位置情報（GPS）・カメラ情報・撮影日時などのメタデータが無い。向きは消す前に画素へ反映する。`dist/` の画像に GPS・カメラ情報が無いことを検査で確認し、あればビルドを止める（Astro は元の画像を `dist/_astro/` にそのまま出すので、Astro の変換には頼らない）
- [ ] サイトのビルドが中継リポジトリを読み、日記がページに出る。**取り込みに失敗したら CI（`WORKERS_CI=1`）のビルドは失敗する**（日記が抜けたまま公開しない）。エラー文に原因の候補（デプロイキーの削除・中継リポジトリの名前変更）と直し方を書く
- [ ] ローカルでは環境変数で取り込み元を指定して動く。指定が無いときは日記無しで動き、そう警告を出す
- [ ] この公開リポジトリの履歴に日記の本文・画像が入らない（取り込み先は `.gitignore`。push の前に検査で確認）
- [ ] vault に push してから 1 時間以内に、人の手を介さずにサイトが作り直される（vault 側の Action は 1 時間おきの予定実行 + 手動実行。中継リポジトリに変更が無いときは Deploy Hook を叩かない）
- [ ] 日記はクローラーに載らない（検査で確認）:
  - 日記の本文が出るページはすべて `<meta name="robots" content="noindex, nofollow, noarchive, nosnippet, noimageindex">` を持つ
  - `public/_headers` で日記のパスに同じ値の `X-Robots-Tag` を付ける
  - サイトマップに日記の URL が無い
  - robots.txt で日記のパスを AI の学習用クローラー（GPTBot、ClaudeBot、CCBot、Google-Extended など）とアーカイブ（ia_archiver など）にだけ断る。検索エンジンは robots.txt で止めない（止めると noindex が読まれず、URL だけ載ることがある）
- [ ] Obsidian 独自の書き方（`[[...]]`、`![[...]]`、`> [!info]` など）が、サイトで崩れずに出る

## 方式（2026-11-28 時点の合意）

```
obsidian-personal (private, Obsidian の自動バックアップで push される)
  └ GitHub Actions（1 時間おき + 手動）: このリポジトリを取ってきて、その選択スクリプトを vault に対して実行し、
    publish: true の日記と参照画像（メタデータを消したもの）だけを写す。変更があれば Deploy Hook を叩く
      ↓ (中継リポジトリのデプロイキー A: 書き込み可。vault の Actions の secret)
diary-public (private, 仮の名前)
      ↓ (中継リポジトリのデプロイキー B: 読み取り専用。Cloudflare のビルド用の secret)
takumifukasawa.com のビルド: 取り込み → Astro の collection → ページ
```

- vault リポジトリをサイトのビルドから直接読まない。読むと private の日記を含む vault 全体がビルド環境に渡る。
- vault 側の Action は薄くする（このリポジトリを checkout してスクリプトを動かすだけ）。選び方・参照画像の探し方・メタデータの除去・Obsidian の書き方の変換は全部このリポジトリの tooling に置く（テストと検査が回せる）。
- 鍵は GitHub のデプロイキー（1 リポジトリだけに効き、期限が無い）。期限のある token にすると、切れた日から取り込みが失敗し、作品の push も含めてサイトの更新が全部止まる。
- 画像はノートの隣に置く（vault の添付ファイルの場所は 2026-11-28 に「現在のファイルと同じフォルダ」に変えた）。取り込みは Obsidian と同じくファイル名で探すので、置き場所には依存しない。
- 画像のメタデータは写すときに消す。**Astro は変換した版とは別に元の画像を `dist/_astro/` にそのまま出す**（2026-11-28 に確認: `dist/_astro/20200304003623.B4GN-b6r.png` が `src/assets/blog/context2d-cpu-raymarching/20200304003623.png` とバイト単位で同一）。

## 決定ログ（日付・決めたこと・理由・落選案）

- 2026-11-27: 日記の本文はこの公開リポジトリにコミットしない。private の中継リポジトリをビルド時に読む。
  落選: このリポジトリを private にする（作品のコードを公開しておきたい）。日記をこのリポジトリに置く（私的な日記が混ざる）。
- 2026-11-28: 文章を書く場所は Obsidian に揃える（日記は私的な日と混ざるので vault から動かせない。ブログを分けると書く場所が 2 か所になる）。
  `src/content/lab/*.md`（作品のページ情報）はこのリポジトリに残す。作品の作り方・Claude とのやり取りは Obsidian で書き、slug でつなぐ。
- 2026-11-28: 公開するかは vault 側で `publish`（チェックボックスのプロパティ）で決める。フォルダで分けない。
  理由: 書くたびに移す手間が無い。付け忘れても出ない側に倒れる。落選: 出さない日を `99_archive/` に移し `01_daily/` を公開専用にする。
- 2026-11-28: 公開は遅らせない（`publish: true` を付けたらすぐ出す）。留守の時期が分かる書き方は、書く側で気をつける（ユーザーの判断）。
  落選: 日付から N 日経った日記だけを出す。
- 2026-11-28: 日記は検索に載せない（noindex + サイトマップから外す）。日記の本文を、検索に載せるページに出さない（ブログの一覧に混ぜるなら、一覧も noindex にする）。
  理由: 一度載ると消すまで数日〜数週間かかる。落選: robots.txt で止める（noindex が読まれず、URL だけ載ることがある）。
  AI の学習用クローラーとアーカイブは robots.txt でも断る。Cloudflare の WAF で日記のパスへのクローラーを拒否するのは、上を作った後にユーザーが入れるか決める（ダッシュボードの操作）。
  日記の画像は Astro が `/_astro/` に出すのでパスでは狙えない。`noimageindex` で画像検索に出さない。
- 2026-11-28: 画像は参照されている分だけを中継リポジトリにコピーする。落選: R2 に置いて配信する（縮小・og:image を自前で持つことになり、vault 側に R2 の鍵が要る）。
- 2026-11-28: 中継は非公開の git リポジトリ。何がいつ公開・非公開になったかを履歴で追える。
  落選: R2 の非公開バケットを中継にする（手間は同じだが履歴が残らない。「跡を残さない」利点は、vault の履歴に全部残っているので実質無い）。
  手元の Mac でビルドして公開する（スマホで書いた日記が自動で出ない。Workers Builds の自動ビルドと食い違う）。
  vault の Actions でビルドして公開する（公開の経路が 2 本になり、作品の push で日記の無いサイトに上書きされる）。
  Cloudflare のビルドが vault を直接読む（vault 全体がビルド環境に渡る）。公開する日記だけこのリポジトリに入れる（`false` に戻しても公開の履歴に残る）。
- 2026-11-28: 鍵はデプロイキー。落選: fine-grained token（期限が来るとサイトの更新が全部止まる）。classic token（全リポジトリに効く）。
- 2026-11-28: 画像のメタデータは写すときに自分で消す。落選: Astro の変換に任せる（元の画像がそのまま `dist/` に出る）。
- 2026-11-28: vault 側の Action は push のたびではなく 1 時間おき + 手動。理由: vault は Obsidian の自動バックアップで 5 分おきに push される。書いている途中の版が 5 分ごとに出ることもなくなる。
