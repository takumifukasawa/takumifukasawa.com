# lab/core — 共通化の規律（3 回ルール）

`lab/core/` は sketch 間で共有するコードの置き場。**最初は空**で、育て方は「作品 → 共通化 → 小さな framework」の順を守る。
詳細と背景: `../../docs/spec/publish-pipeline.md`（core/ への共通化ルール）、`../../docs/decisions/0003-code-placement.md`（昇格モデル）。

## 常に守ること

- `core/` に追加してよいのは、**同じコードを 3 つ以上の sketch で書いた後**だけ。
  2 件以下なら sketch 側にコピーで置く。コピーは負債ではなく、共通化の材料を集めている段階。
- **依存の向きは sketch → core の一方向**。`core/` から `lab/<NNN-slug>/` を import しない。
- `core/` に移したら、元の sketch を書き換えなくてよい（ビルド済みの成果物は固定されている。決定 0001）。

## やらないこと

- 将来使うかもしれない抽象・汎用化・オプション引数を先回りして `core/` に置かない。
- 「3 件目でたぶん使う」で 2 件目の時点に共通化しない。**3 件目を実際に書いてから**。
- 共通 bootstrap（全作品が通る初期化コード）を作らない。ライブラリは作品ごとに import する。
- shader の核・数式・GPU アルゴリズムを AI が `core/` に書き切らない（`../../AGENTS.md` の AI との分担。骨組みを示して止まる）。

AI にコードを書かせるとき最も効く規律（指示が無いと共通化を先回りしてやりがち）。迷ったら `core/` に入れない方を選ぶ。
