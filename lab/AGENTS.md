# lab — 作品のソース置き場の規律

`lab/<slug>/` は作品 1 件のソース。ビルド成果物は `public/lab/<slug>/` に固定される（決定 0001）。

## コードを書く前に

**`../docs/coding.md` の「lab」の節を読む。** class を使わない、文字列で参照されるプロパティはクォートする（terser がプロパティ名まで mangle する）、
破損はビルド済みの成果物で確かめる、などの規約がある。

## three.js の完成品をどこまで使うか

**使ってよい。** `MeshStandardMaterial` / `CubeCamera` / `*Geometry` / `OrbitControls` / `EffectComposer` の各 Pass、いずれも禁止ではない。

ただし **その sketch の主題になっている部分は自分で書く**。主題でないものに時間を使わない。

狙いは「three.js 特有の書き方しか身に付かない」のを避けることであって、three.js を避けることではない（`../AGENTS.md` の目的）。
完成品は隠してくれるので、隠されたものは学べない。だから **何が主題かを先に決めて、そこだけ開ける**。

例（`lab-archives/mirror-sphere`。棚上げ済み。決定 0006）:

| | 主題か | どうしたか |
|---|---|---|
| キューブマップ 6 面の向き、FBO への描画、反射ベクトル | **主題** | 手で書いた |
| 球のジオメトリ | 主題に近い（巻き順と極が反射に効く） | 手で書いた。実際に巻き順が逆で反射が壊れた |
| bloom | 主題ではない | 手で書いたが、`UnrealBloomPass` でもよかった |
| カメラ操作、ポインタの座標変換 | 主題ではない | three の API を素直に使う |

## 常に守ること

- 作品の `vite.config.ts` は作品ごとのコピーにする。共通ファイルからの import にしない
  （成果物は作品ごとに固まるので、共通設定の変更が `lab:rebuild --all` で古い作品を変えないように）。
- 共通化は 3 回ルール（`core/AGENTS.md`）。

## やらないこと

- shader の核・数式・GPU アルゴリズム・rendering logic を AI が書き切らない（`../AGENTS.md` の AI との分担。骨組みを示して止まる）。
